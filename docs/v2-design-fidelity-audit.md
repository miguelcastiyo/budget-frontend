# Prototype fidelity audit and correction checklist

Baseline: `budget-frontend-v2/components/budget`, compared with the production v2 presentations and their controllers. The prototype uses a mock store; its values and persistence are not production specifications. This is a source audit, not a claim of a completed visual comparison on physical devices.

- **Shell — visual / interaction:** Prototype uses Home, Activity, central Add, Review and More, with a 14rem sidebar on desktop. Production had six items and different labels, icons and ordering. First pass restores the prototype order and geometry, using real routes and the existing Review permission and count. More currently opens Settings, not the prototype's grouped More screen; Insights and Funds are no longer direct navigation items. A prototype-aligned More screen with real links is future work.
- **Overview — visual / intentional v1-only:** Prototype has a month switcher, large left-to-spend summary, three fine category bars, conditional Review/closeout rows and date-grouped recent transactions. Production added onboarding cards, Funds and tag breakdown sections and category drill-downs. First pass removes those v2 extras, retains the production budget setup and closeout paths, and adopts the prototype's compact recent row and savings status. Classic keeps the full presentation. Production totals include Savings as determined by the authority; the prototype's mock calculation is not used. Full closeout detail remains a safety-oriented disclosure and differs from the prototype's closeout row.
- **Add / Capture — corrected in second pass:** Quick Capture now uses the prototype hierarchy: compact header, large amount control, description, Today/Yesterday/Other controls, keypad with Done, and bottom actions. Full Entry has a compact mode switch, category before Tag, searchable Tag/Card picker rows, inline Tag/Card creation, and Context selection through the existing searchable authority-backed sheet. The same editor and pending-write controller remain mounted through mode changes. The authority handles saving, validation, retry and reconciliation. Full Entry intentionally omits Notes, Split and recurring creation controls; those stay in Classic as v2 parity candidates. Existing transaction edits continue to use the complete production editor so hidden attributes are retained; no edit payload fields were removed.
- **Review — visual / interaction:** Both implementations use category then Tag confirmation, but production retains queue status, sync/conflict and recovery controls around its card and production details editor. Compare swipe feedback, transitions, tag choices and completion geometry with the prototype; keep explicit confirmation, Undo, blocked/uncertain writes, capability gating and safe recovery. No Review changes in this pass.
- **Activity / transaction details / filters — visual / interaction:** Prototype has a compact date-grouped ledger, inline search and filters and a small detail sheet. Production retains the broader filter sheet, saved views, pagination, summary metrics and production detail/editor controls. Recompose around prototype rows and filters in a later pass; the additional filters and metadata are v1 parity candidates. Keep real sorting, paging and financial mutations. No Activity changes in this pass.
- **Insights — visual / intentional v1-only:** Prototype provides a compact spending-by-tag panel; production exposes ranges, snapshot, budget comparisons, rhythm, recurring, weekday charts and notable transactions. These additional reports are v1-only candidates. Production values and real drill-downs must remain authoritative when a later presentation is selected.
- **Budget — visual / intentional v1-only:** Prototype supplies a small monthly-budget panel and effective-date list; production exposes full income/allocation forms, previews and version history. Full configuration remains accessible in Classic; decide how much editing the prototype panel needs before replacing production presentation.
- **Funds and Savings Plans — visual / interaction:** Prototype presents compact fund balances and goals; production uses full fund list/detail, ledger, editor and confirmation workflows, and a separate Savings Plan experience. Extra ledger and planning controls are parity candidates. Only expose actual supported fund operations and retain linked-entry, closeout and retry protections.
- **Settings / management / Vault — visual / intentional v1-only:** Prototype's More groups planning, look-back, organization and account rows; several panels are informational or explicitly disabled. Production has separate full Settings, taxonomy, recurring, Data, Vault and Devices screens with existing portals. Grouping, theme selector and sheet geometry differ; disabled prototype actions must not be presented as successful operations. Account security, Vault recovery and interface switching remain available even if the future v2 menu is simplified.

## Follow-up checklist

1. Implement the real grouped More landing and destinations, including Insights and Funds, with a route to interface preference and Vault.
2. Compare matching desktop and mobile rendered screens against the prototype and record typography, color, spacing and sheet differences; repeat in light/dark themes. For Add, specifically compare native keyboard behavior, keypad spacing and small-height devices.
3. Recompose Add, then Review, then Activity using prototype presentation and real authority commands. Test draft preservation, in-flight guards, uncertain outcomes and Classic switching at each step.
4. Triage the remaining prototype panels separately. Maintain a list of intentionally Classic-only controls and never substitute mock values or pretend a disabled operation succeeded.
